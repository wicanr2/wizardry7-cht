# M3 前置筆記 2：文字有兩類——烤進點陣的 vs 執行期繪製的（2026-09-21）

## 重大發現：巫術7 的選單文字烤在 .VGA 點陣圖裡（confirmed）

實測鏈（probe -trace @246.885M ＋ z-run 開檔紀錄）：

1. 開機 #239,897,574：`MAINSCRN.VGA → 6289:0000`（64,000 bytes 整檔載入）。
2. #246,884,928 起：驅動 blitter（740C:0604 的 movsb）**從 6289:2C9F 起**
   把像素資料搬進 A0000——一次大區塊，來源就是 MAINSCRN.VGA 的載入段。
3. 400M 後的畫面（e141d21a）與 MAINSCRN.VGA 檔案**逐位元組 58,055/64,000 相同**
   ——差異處＝執行期後來覆蓋的少量內容。

⇒ **「CHARACTER MENU / ADD CHARACTER / …」這些選單文字不是執行期畫的，
是烤在 MAINSCRN.VGA 點陣圖裡的**。同理 PCVWSCRN.VGA（party 畫面）。
（這也是為什麼 blitter 在 450M 只被呼叫 40 次：整張底圖一次搬。）

## 執行期繪製的既有線索

- 印字經過 VGA.DRV blitter（0x4B5）——但**文字字形由上層展開後才呼叫**
  （blitter 只收大區塊；字形展開在上層常式，位置待定位：
  OnCall 呼叫端分群只在 blitter 40 次大呼叫出現過一個呼叫端，
  文字繪製常式應該**不走 blitter**，而是直接寫 A0000 的字形展開迴圈）。
- 字型：VBFONT0-3.VGA 載入在 728A/7B0E/7B80/7BB6/7D88 段
  （trace 實測這些段在 246.5M 的輪詢窗口有被存取）。
- 選單熱點表（ds:59FE）座標與畫面選單列對應——UI 命中在 driver 層。

## 印字常式定位（trace 實證 2026-09-21 深夜）

- trace（246.885M 文字繪製瞬間，20,000 道）：執行流 = resident(0110) 3,825 行
  ＋ driver(740C) 2,175 行；**所有 0110→740C 轉換的呼叫端都是同一點
  0110:4091**（＝ sub_1408D 的 `call cs:dword_12D8F`，IDA 0x1408C）。
- 亦即：**繪圖服務全部經過函式指標表 cs:12D8B/12D8F… 的間接遠呼**，
  指標內容由 resident 依「要畫什麼」動態填入。
- driver 端執行熱點（檔案 offset）：0x1317-0x1399（熱點/滑鼠輪詢服務）、
  **0x504 的 movsb（blitter）在此窗口 0 次**——246.885M 的選單底圖搬移
  發生於更早（#246,884,928-246,885,257 已在 trace6 前段捕獲，
  movsb DS=6289(MAINSCRN 載入段) ES=A000，一次整檔搬移）。
- **修正**：選單文字不經 driver blitter。文字字形由 resident 的
  字形展開常式直接寫 A0000（trace 中 0110 段的高頻寫入迴圈）。
  印字常式 ＝ resident 0110 段、呼叫 sub_1408D 之前的字形展開程式碼，
  IDA 位置約 0x12E00-0x13000（sub_12EA3/sub_1308 一帶）——下一輪細讀。

## M3 的正確切入（取代前一版「烤入點陣」假設）

1. MAINSCRN.VGA＝乾淨背景（無文字）。選單文字由 resident 的字型展開
   常式執行期繪製（字型：VBFONT0-3 已載入 728A/7B0E/7B80/7BB6/7D88 段）。
2. 攔截點＝該字型展開常式（resident 內，非 driver）：
   字元索引 → VBFONT 字形 → A0000。換字＝在展開時改寫。
3. 字串來源：MSG.DBS（262KB 壓縮）——解壓格式＝M3 主體。
4. PCVWSCRN.VGA 的烤入文字僅右緣直式 EXIT 等少量，直接點陣替換即可。
