# M3 前置筆記：印字常式定位的切入點（2026-09-21）

目的：翻譯層要在「原版畫字的那一刻」攔截。本筆記記錄目前已知的
繪圖管線與印字常式的定位方法。

## 已確認的繪圖管線（confirmed）

- **所有畫面繪製都經過 VGA.DRV 的 blitter**：檔案 offset 0x4B5 起
  （載入後模組 0x5B5、執行期 740C:05B5）：
  - `di = y*320 + x`（mode 13h 線性定址）
  - 從 DS:SI `rep movsb` 一列一列搬到 A0000（寬高來自參數）
  - 前後各呼叫一次 sub_1308／sub_67F（推測為更新前後處理）
  - 內部 0x504 的 `rep movsb` 即 probe `-watch` 觀察到的寫入點
    （ip=740C:0604，51,298 筆寫入監看實測）
- 底圖（MAINSCRN.VGA 等）與文字字形**都走這個 blitter**；
  差別在呼叫端與區塊大小（底圖＝大區塊，字形＝8×8/8×16 小塊）。

## 印字常式的定位方法（下一步）

1. dosgolem oracle `OnCall` 掛 blitter 入口（執行期線性 0x74675），
   記錄每筆呼叫的呼叫端 CS:IP 與參數（寬高/來源位址）。
   —— 比照 psychic-war docs/re/014 的 print-trace 方法。
2. 呼叫端分群：大區塊＝底圖/圖形；**寬 8、高 8/16 的小區塊連發＝文字字形**。
3. 字形來源追蹤：字形資料在 VBFONT0-3.VGA 載入的段落
   （0x7B0E/0x7B80/0x7BB6/0x7D88，開機載入，walk log 證實），
   blitter 的 DS:SI 來源會落在這些段。
4. 找到字形繪製常式後，往上追**字串來源**（MSG.DBS 解壓後的字元索引）
   —— 即 M3 的文字抽取入口。

## 攔截點的設計含義

- 攔截選項 A：在字形 blitter 呼叫處攔（印字常式層）——拿到字元索引，
  換成中文字形區塊。
- 攔截選項 B：在 blitter 內部攔（依來源段判斷是否字形）——通用但粗糙。
- psychic-war 的 xlate 走 A（印字常式層），巫術7 預期同路。

## 文字樣式（使用者提醒 2026-09-21）

攔截時每筆印字呼叫都要記下**樣式資訊**，中文置換才對得上：
- 字形尺寸（8×8／8×16——中文要 16×16 以上，不縮字，rulebook/81）
- 座標（x,y——中文雙寬會影響置中/分頁計算）
- 顏色（前景/背景——mode 13h 在資料裡或獨立參數）
- 來源字型（VBFONT0-3 哪一個——大小字混排的畫面要分別處理）

追蹤工具（blitter OnCall）每筆記錄：呼叫端 CS:IP、x/y/w/h、來源位址。
