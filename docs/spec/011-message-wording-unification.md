# 011：同義訊息文案逐組統一

狀態：DRAFT；2026-10-01；[#24](https://github.com/wicanr2/wizardry7-cht/issues/24)。
入口[R672](../goal/R672-delivery-prerequisites.md)，來源與候選證據[019](../re/019-catalog-migration.md)。

## 為什麼要做

使用者選擇先逐組統一譯文再遷移。182組同原文差異經逐組審閱，174組有同義候選，
其中三組短句的全形字數尚未過門檻；八組不同語意或未知用途仍需要情境。
先完成有充分證據的同義文案，不為TSV遷移刪掉資訊，也不以舊載入順序裁決。

## 固定候選與可採用集合

`workplace/r700/candidate-messages.json`組合兩批各91組及必要鄰列校正，改動371列。
輸入雜湊、174組裁決與完整194組舊正規化碰撞集合見`candidate-unification-audit.json`。
`workplace/r708/candidate-lint.json`曾以Unicode東亞寬度W／F計數，漏計Big5雙位元組的省略號；
獨立審查`workplace/r706/message-spec-review.json`指出該檢查不足。
`Ort!`候選「歐特！」有3個全形字，超過原文4字元的一半；
`Hoyo...`候選「霍喲……」4字超過3.5，`Bodendoi...`候選「波登多伊……」6字超過5.5。
既有文案超限不能當作豁免；保留原有收據，寬度改依逐字Big5編碼長度2計數。

現行候選`workplace/r716/candidate-messages.json`排除上述三個整組，
採171組與其必要鄰列，共373列文案變更。
`r716/candidate-audit.json`核對完整182組分割、171組中文一致與精確差異；
29列來自既有手填`Z`、344列來自既有批次合併表，雙來源交集0。
候選以道具校正後正式表為基礎，保持010已校正的3805、5506兩列，不能整檔覆蓋舊候選。
兩組I.U.F.句子全部使用「恩帕尼帝國軍」，避免混合ASCII在既有烘製路徑被略過；
28118／28418的thousand明確譯為「一千」，不是「上千」。
11796／11991／12191的diseased head採「患病的首腦」，僅為病況措辭的強推論，
不增添疾病機制或心理診斷。
排除整組，不能只排單筆而默默把該組標為統一完成。
PSIONIC、POISON、STONE、FORCE、LEAVE、TRUNK、HER、NAME:原樣待核；
Ort!、Hoyo...、Bodendoi...的字數／畫格問題另待證據。
這十一組不藉本規格解除008的遷移阻擋。
現行候選剩餘原文歧異11組；排除空鍵及規格002已拒絕的純槽`$`後，
烘製正規化25組、執行期正規化24組。未排除的全來源口徑為26／25組，
不能與舊194組全來源口徑混比。三者分開保存完整集合。
既有數字／低位控制碼衝突仍待008處理，不能以來源ID猜補。

## 擬定契約

- U1：僅修改經審查的171組同義文案及必要鄰列。完整英文、訊息來源ID、原始排序、
  `dy`及原版分頁保持不變；不能改normalize、選caller、增加情境或以ID當執行期鍵。
- U2：以逐組候選理由及跨列對齊證據審閱所有採用列，不只看中文是否一致。
  專名遵守既有譯名表，地理、代名詞、稱謂及結局資訊不增刪。
  原始MSG來源位置只證明文本排序；正常跨列分頁仍需獨立畫面驗收。
- U3：正式遷移前同步目前`text/story-trans.json`及有效產生器來源。
  `tools/gen_trans.py:Z`涵蓋的變更同步該字典；其他變更同步既有`batches-merged.json`。
  若同ID同時存在兩者也須一致，不新增不存在的批次ID，不重寫原始批次收據。
  產生器重生結果應與正式表逐列一致；TSV遷移時舊中文來源依008退場。
- U4：比較修正前後精確差異集合；每列完整英文／控制碼／placeholder數量及其他欄位相同，
  中文可Big5編碼，全形字數符合翻譯指令，兩字型缺字0。
  全量原文差異及正規化碰撞重新對帳；未解除的歧義仍列出，不能任由最後覆寫而稱全部完成。
- U5：先保存統一後基準，再做TSV格式遷移；本次文案變更與格式回歸分開驗收。
  兩字型、2×／3×的31故事頁、6旁白頁、代表一般選單及F1回歸，
  原版Mem／A000／Pal／Step應與相同輸入的修正前相同；全圖像素由獨立原文／譯文來源核對。
  畫面差異須落在批准文案區域，不放寬既有故事匹配／清場或防禦閘門。
- U6：未在正常玩家路線觸發的同義訊息只稱文案與靜態驗證完成，不宣稱全171組上屏。
  後期結局仍需合法正常checkpoint，不修改存檔、原版記憶體或使用作弊建立收據。
