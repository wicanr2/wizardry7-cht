## 為什麼要做

使用者定案（2026-09-30）：F1 開關說明；開啟時暫停遊戲；內容含前端快捷鍵、基本操作、
目前畫面說明、譯名對照。目的同中文化：讓不諳英文的玩家知道怎麼操作。

## 規格

### R1 按鍵

- F1：開啟／關閉說明。Esc：關閉說明（僅在說明開啟時由前端處理；說明關閉時照舊送原版）。
- 說明開啟時：← →（或 PgUp／PgDn）切換頁；其他按鍵、字元、滑鼠一律不送原版，也不排入佇列。
- F1 永遠由前端處理，不送原版。依據：H2（防拷、旁白讀走 F1 但無可見作用，且有正對照）。
  主選單（H3：鍵盤正對照無效，原版在此只認滑鼠）與迷宮（H4）是否使用 F1 未量到，列入風險。

### R2 暫停

- 說明開啟期間，機器 goroutine 不呼叫 `o.Run`、不投遞任何輸入，包括游標位置（`o.MoveMouse`）、
  點擊（spec 004 的 `sh.clicks`）、右鍵、按鍵與字元；Update 在說明開啟時也不把這些排入佇列。`o.Steps()` 不變。
- 關閉後照常推進；關閉當下的游標位置在下一輪照常轉發。
- 決定性：暫停期間步數凍結，所以牆鐘停多久都不改變之後各步數的原版狀態；`-help-for` 用牆鐘不影響 R6 驗收 1 的雜湊比對。

### R3 內容來源

- 自製文字放 `text/help.zh-TW.tsv`（UTF-8，欄位：`key`、`zh`、`source`）。`source` 註明依據
  （`docs/re/015` 的 H 編號或規格條號），沒有依據的操作不寫。
- 頁面：
  1. 快捷鍵：只列已實作的前端鍵（F1、Esc、翻頁）。
  2. 基本操作：H7–H10 的操作，且每一條都要在 spec 004 完成後的互動前端（Xvfb＋xdotool 真實輸入）實測通過才列入；
     實測未過的不寫。鍵盤只寫字元與 Enter（前端走 DOS stdin，H10）；方向鍵等非字元鍵不寫（H5）。
  3. 目前畫面：依 H6 辨識；辨識不到時顯示通用內容並註明「此畫面暫無專屬說明」。
  4. 譯名對照：由工具從 `text/story-trans.json` 依訊息 ID 範圍產生（種族 100–110、職業、咒語等，範圍在工具內列明），
     產物 `text/help-names.zh-TW.tsv` 進版控；英文欄為原文（依 2026-09-19 定案原文可進版控）。
- 手冊內容不摘錄；手冊防拷關鍵字不出現在任何說明。

### R4 畫面辨識

- 以開啟說明當下 `shown` 事件的英文原文判定，規則依 H6：
  含 `SECURITY CLEARANCE` → 防拷；含 `OK` 與 `CANCEL` 且含 `ADD CHARACTER` → 建角；
  含 `CHARACTER MENU` 或 `START NEW GAME` → 主選單；否則通用。依上列順序取第一個成立者。
- 順序有實測依據：`workplace/r663/zh3/hdat-286000000.json`（防拷畫面）的 shown 同時含
  `SECURITY CLEARANCE`、`CHARACTER MENU`、`ADD CHARACTER`、`START NEW GAME`；272M 快照亦同。
  主選單規則若排在前面會誤判。R6 驗收以這兩份資料做自動檢查。

### R5 字形與繪製

- 新工具 `tools/re/bake_help.py`（不改 `bake_font.py` 的 xlate 管線，只 import 其 `glyph_of`）：
  讀 `text/help.zh-TW.tsv` 與 `text/help-names.zh-TW.tsv`，蒐集所有字元，逐字產生字形：
  - Big5 雙位元組字：`glyph_of`（涵蓋 `SPCFONT.15` 與 `stdfont.15`），寬 15、15 列、每列 16 bit；
  - ASCII 0x20–0x7E：`ascfont.15`（H11），寬 8、15 列、每列 8 bit；
  - 其他字元（無法編 Big5、或不在兩種字型範圍）：列出後以非零碼結束，不產出檔案。
- 產物 `workplace/bake/help.json`：
  `{"glyphs": {"<字>": {"w": 寬, "rows": [15 個整數，高位對齊字寬]}}, "pages": [{"id": 頁代號, "title": 標題, "lines": [字串…]}]}`。
  `pages` 由 TSV 的 `key`（格式 `<頁代號>.<兩位序號>`，序號 00 為標題）排序組成。
- 前端另寫說明專用的繪製函式：逐字依 `w` 前進（字距 2 px），不共用 `textEv` 的正方形字形假設。
  `help.json` 缺檔時 F1 顯示一行英文提示「help.json missing」並記 log。
- 半透明深色面板覆蓋整個視窗；版面畫在 `-scale` 倍率畫布（預設 3×＝960×600）；每頁超出一頁高時截斷並記 log。

### R6 可驗證性

- 旗標 `-help-at <步數>` 與 `-help-for <毫秒>`：到該步數開啟說明，經過指定牆鐘時間後關閉（測試用）。
- 與 `-draw-at` 同步數時：autos 在同一輪迴圈內依序執行，`-draw-at` 只設「下一次 Draw 存檔」旗標，
  實際存檔發生在之後的 Draw；此時說明已開啟且機器暫停，截圖實務上為說明畫面。前提：同一 `at` 的兩個 auto 之間
  `sh.mu` 會短暫解鎖，Draw 理論上可能插在中間（窗口為微秒級，畫格間隔約 16 ms）；實作時把 help 的 auto 排在 draw-at 之前以消除此情形。
- 比對以 `-hd-at` JSON 內的 `Step` 為準，不以檔名步數為準（autos 可能晚於門檻才執行）。
- 驗收：
  1. 同路線 `-hd-at 300000000` 下，有無 `-help-at 286000000 -help-for 3000` 兩種跑法的原版記憶體／A000／調色盤雜湊相同。
  2. 說明開啟期間 log 記錄開啟與關閉時的 `o.Steps()`，兩者相同。
  3. Xvfb 下 `-draw-at 286000000` 取得說明畫面截圖（防拷畫面時開啟，目前畫面頁應為防拷說明）。
  4. `bake_help.py` 對含缺字的暫存 TSV 非零結束且不產出檔案；正式 TSV 產出 `help.json`。
  5. lint：`help.zh-TW.tsv` 中「基本操作」頁每一列的 `source` 必須指向一筆已記錄通過的前端實測（`docs/re/015` 追記的測試編號），否則 `bake_help.py` 失敗。
  6. R4 辨識規則對 `r663/zh3` 的 272M／286M JSON 與 `r665/maze` 的 1470M JSON 分別判為防拷、防拷、通用（自動檢查）。

## 風險與未決

- H3、H4：主選單與迷宮若原版使用 F1，會被前端擋掉。
- H5：前端非字元鍵走 IRQ1，原版多半收不到；說明畫面不寫「用方向鍵移動」之類未證實的鍵盤操作。
- 迷宮、戰鬥、旁白的專屬說明需要可辨識訊號，另案。
