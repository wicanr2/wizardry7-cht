## 目的與證據

resident印字入口0110:3895、返回0110:0fcc、字型0，x150及y150／156／162／168／174／180。六列各15字元，原版逐字座標150、156至234，返回時x240，y保持。前十格包含姓名及空白；後五格為碼，原版碼帶x210..240、y..y+6。未選取的差異為195底色變180前景；選取後為1白底變0黑字。初始六次與首列、末列選取後十二次共十八次全離屏補量，碼帶與已知姓名格外差異0。實際GUI完成新增、兩次選取、取消、正常退出；探針只補量，不取代GUI。

## 擬定實作契約

1. 正式文案新增`text/roster.zh-TW.tsv`，沿既定五欄`en、zh、context、dy、source`。本家族`context`只接受`character.add.roster`、`dy`只接受0、`source`只接受`runtime:0110:0fcc`；source只作出處，不當查找鍵。不讀MSG或改008三個既有catalog的遷移狀態。
2. 六個英文碼為M-FIG、F-FIG、M-THI、M-PRI、M-MAG、F-ALC。文案依既定職業譯名補性別字，候選依序男戰士、女戰士、男盜賊、男牧師、男法師、女鍊金術士。正式譯文只放TSV，產生的JSON只存文案與原生字模，不在Go複製中文文案。六鍵非空、不重複，欄數、UTF-8、字型覆蓋及原生寬度強制檢查。本家族依已量90像素碼欄驗寬，覆蓋一般英文長度二分之一的文案估算；不省略既定職業譯名。
3. 只在scale3、精確resident返回、字型0、x150、既有六個完整英文鍵與其已量y相符時識別碼。名字與padding照原版保留；不把相同碼在其他caller或任意姓名列收為新路徑。每次仍比完整英文及呼叫訊號，後五字元只作已確認子區域，不將前十格視為通用record格式。
4. 在原版印字入口與匹配SP的返回取既有唯讀前／後快照，建立只含碼帶的事件。範圍固定x210..240、y..y+6；拒絕空差異、未知色號、碼帶以外非已知姓名筆畫差異、或其他未證實變化。英文姓名不列入清除範圍。碼帶狀態沿001的原版A000／離屏判斷及游標容忍，事件失效就移除中文，不在遊戲記憶體寫入。
5. 以原生15／16列、每字加2像素間隔在x210×3、y×3畫譯文，整串寬不超90、字高不超18。HD及Draw使用同一字模，不更改原版命中區、輸入、存檔或規則。不得回到英文姓名時留部分中文或殘影。
6. 2倍畫布本輪保持既有英文及可辨認缺譯紀錄。其列距12小於原生字高15／16，欄寬60小於最長83／88。本輪不縮字、改職業譯名、重排姓名或自動切換倍率；2倍完整中文另有排版閘門，不以此宣稱全部倍率完成。既有3倍預設及021兩按鈕修正不改。
7. 資源缺檔、格式錯誤、缺字、未知caller／字型／座標／英文、倍率不符或狀態無法確認時保留原文並記錄。未知分支保持未量，不因單測標CONFORMED。

- 由新`tools/re/bake_roster.py`解析`text/roster.zh-TW.tsv`。五欄表頭精確為`en\tzh\tcontext\tdy\tsource`，順序及欄數固定。UTF-8且不帶BOM，CRLF可按行尾讀取；空白列、重複英文鍵、缺欄、未知context、非0的dy及非精確`runtime:0110:0fcc`拒絕。這六列皆無控制碼或placeholder，本家族只收直接字元，不接受反斜線跳脫或欄內控制字元。英文必須恰為六個已量碼的集合，譯文非空、僅含可用原生中文字形，不能混入姓名。008三個舊家族的source語法及DRAFT狀態不變。
