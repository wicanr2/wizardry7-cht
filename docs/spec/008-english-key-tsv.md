# 008：譯文以英文原文為鍵的TSV來源

狀態：DRAFT；2026-10-01；議題#24；證據[研究019](../re/019-catalog-migration.md)。
本草稿尚有情境辨識與控制碼處置缺口，不授權正式遷移或修改原版語意。

## 為什麼要做

使用者2026-09-29定案：UTF-8 TSV是玩家可見譯文的唯一正式來源，英文原文含控制碼為鍵，
MSG訊息ID只作出處。2026-10-01選擇先逐組統一同義文案再遷移，
不以舊字典最後寫入文案作默認裁決。真正不同語意依已證實的情境保留，不能抹去資訊。

## 擬定契約

- R1：正式訊息、怪物、物品文案分別為`text/messages.zh-TW.tsv`、`monsters.zh-TW.tsv`、
  `items.zh-TW.tsv`。共同表頭`en<TAB>zh<TAB>context<TAB>dy<TAB>source`；F1現有兩份TSV保持原格式。
  `source`保存訊息ID或原始資料索引列表，不參與翻譯查找。翻譯鍵為完整原文與已核准情境。
  - `en`、`zh`為還原跳脫後的Unicode字串；原文大小寫、空白、標點與控制碼全保留，
    不做trim、大小寫折疊或Unicode正規化。原文須非空並與指定來源相等；譯文須非空。
  - `context`為`any`或已審查訊號註冊表中的符號，符合`[a-z][a-z0-9._-]*`，不允空欄或未知符號。
    註冊表須保存原始呼叫／座標／結構訊號與證據；重疊、無法辨識、或歧義未解除時回原文並記錄。
  - `dy`為無空白的有號十進位整數、單位是原版DOS畫面像素，不能留空；
    目前8,825筆全為0，遷移只允0，新增偏移須經對應規格核准，不由解析器默認補值。
  - `source`為非空、以分號連接的出處token列表，無空白、不重複；
    家族順序固定為`msg`、`monster`、`item`，同家族按數字索引、monster再按陣列位置排序。
    所有數字欄只允`0`或`[1-9][0-9]*`，不允正負號、前導零、空token或末尾分號：
    `msg:100`、`item:18`、`monster:23:0`；monster末欄是既有`names`陣列位置0–3。
    每個索引必須存在、原文相同、沒有被豁免；不接受保護／輸入詞庫索引。
    出處語法例`msg:1561;msg:5508`只描述多個來源，不是執行期匹配樣式。
- R2：每欄明確跳脫：反斜線`\\`、TAB `\t`、換行`\n`、CR `\r`、其餘低位控制碼與DEL
  `\xNN`。只接受這些跳脫，未跳脫的欄位控制字元、未知或截斷跳脫拒載。
  比對與詞界判定在還原後進行；`\n`後的字母是新詞開頭，不把跳脫字母n當詞的一部分。
- R3：同語意候選先逐組審閱，跨列修正整組採用並保存差異理由；182組每組都須有裁決。
  純格式遷移另外對照「統一後」基準，不能混淆使用者已允許的文案變更與格式造成的回歸。
- R4：同英文不同語意只使用量到的呼叫位置、座標、字型／色彩或資料結構訊號分流。
  不能用訊息ID作鍵、默認取第一／最後、杜撰caller，或用鄰列分類冒充執行期情境。
  無歧義的項目使用通用情境；歧義項目在取得證據與審查前仍是遷移阻擋。
- R5：原文欄及正式譯文按[翻譯指令](../../text/TRANS-INSTRUCTIONS.md)保存控制碼與填槽。
  名字`^`、數字`$`、句中`#`不刪除；高亮記號按指令去除；數量與位置用途分別核對。
  舊覆繪刻意省略名字的行為不能當作正式文案刪掉名字的依據。
- R6：烘製層可產生JSON執行期資料；正式譯文只能從TSV讀取，不在程式或其他JSON複製正式譯文。
  原始英文抽取表仍保存來源資訊；#26擱置資料不改、不加入新catalog／封包。
  流文保留原版資料排序及來源窗口，先以原文和核准情境查譯文；輸出ID僅是來源護欄與診斷。
- R7：lint拒絕重複複合鍵、欄數、UTF-8、跳脫、控碼／placeholder不相容、漏譯、孤兒來源、
  缺字與超出已核准行寬。烘製正規化鍵亦須檢查碰撞；同原文與不同原文造成的碰撞分別報告，
  不以同字形或相同譯文掩蓋原始鍵歧義。未譯字串仍顯示原文並記錄。
  三份catalog須合併檢查複合鍵。跨家族相同鍵且文案／偏移完全相同，只保存一列並合併出處；
  存放檔依訊息、怪物、物品順序選第一個出處家族，這是儲存位置，不是選文案優先權。
  不同文案／偏移則阻擋，先統一或取得情境證據，不能依檔案載入順序覆蓋。
- R8：原版EXE／資料／存檔／比較／輸入只使用原值；所有更動限定顯示層。
  不新增遊戲規則、改原版分頁或讓譯文參與資料查找。

## 必須解除的草稿缺口

1. 八組真正不同語意或未知用途，尚無可用執行期分流證據；須量正常玩家路徑及呼叫訊號。
   三組短句Ort!、Hoyo...、Bodendoi...另有超寬，須取得可用原版文字帶，不能擅縮字、改譯名或省略標點。
   使用者定案十一組全部補齊才交付；其餘171組／373列已依011統一，遷移基準改用這個已驗版本。
2. 控碼差異目前26筆：依[016](016-catalog-control-preservation.md)修正10列，主要四符號28→26、納入低位碼的指定集合32→26；其他高亮及既有名字／數字槽仍須逐筆核對，不能稱全部已驗。
3. 171組統一後，排除空鍵／純槽的烘製25組、執行期24組正規化碰撞仍須核對；
   未排除時為26／25組。舊194組僅為統一前盤點，不能作目前剩餘數量。
   不擅改既有normalize而遺失數字／序數匹配；完整口徑與差異見研究019。
4. 物品對齊依010已校正28個名稱與兩個共用訊息，正式產生器重建一致；
   正常路線尚未觸發這28個完整鍵。三個複合名稱另依012驗收，不能以靜態名稱核對取代上屏證據。

## 擬定驗收

完整數字對帳與所有lint通過；正式來源只有TSV，原JSON及產生器內嵌譯文退場；
兩種字型重建缺字0。統一後基準與TSV烘製資料逐位元相同；
兩倍率31故事頁、6旁白頁、選單、F1、代表情境與正常存讀檔跑同狀態驗證，
原版Mem／A000／Pal／Step相同，像素差異只在批准且已記錄的文案更動區。
未觸發的後期路徑與防禦分支保持未量狀態，不據此宣稱全文完成。

## 正式來源與驗收工具遷移清單

| 類別 | 必須處理的入口 |
|---|---|
| 舊文案 | `story-trans.json`、`monsters-trans.json`、`items-trans.json`、`batches-merged.json`移出正式來源；必要歷史僅留Git歷史或本機研究收據 |
| 正式產生器 | `tools/gen_trans.py`、`gen_monsters.py`、`gen_items.py`移除內嵌譯文，原名抽取仍可維持JSON |
| 烘製 | `tools/re/bake_font.py`、`bake_flow.py`改讀共同TSV解析與查找介面，保留原版來源排序、讀取窗口及英文必要比對 |
| F1譯名 | `tools/gen_help_names.py`按核准語意類別的英文鍵生成既有F1 TSV；不從ID譯文JSON取值，避免重複權威 |
| 批次工具 | `tools/re/trans_merge.py`、`trans_audit.py`及相應批次入口改以候選匯入／lint操作TSV；不得再復活舊正式JSON |
| 獨立oracle | `check_flow.py`、`check_story.py`、`check_native_font.py`、`check_native_gui.py`、`probe_font.py`獨立解析正式TSV；不匯入受測解析器取得預期值 |
| 原版證據工具 | `story_evidence.py`保留原版資料與來源定位；若取譯文改讀TSV，不改其原版窗口或時序證據 |
| 契約與入口 | spec001／002的英文鍵與純槽拒絕契約、spec006正式來源說明、翻譯指令、譯名表、字元清單與README重建入口同步更新 |

遷移前再搜尋所有現行JSON檔名引用，區分歷史記錄與有效生產者／消費者。
歷史證據保留原來源雜湊；禁止改寫舊收據來製造轉換前後相同的假象。
