# 032：人物法術視窗保留未遮住的裝備中文

狀態DRAFT；2026-10-08；[#22](https://github.com/wicanr2/wizardry7-cht/issues/22)、[#28](https://github.com/wicanr2/wizardry7-cht/issues/28)。
入口[R984](../goal/R984-normal-profile-context.md)，證據沿[025](../re/025-ui-localization-coverage.md#r984-normal-profile-context)。

## 為什麼要做

正常人物頁的裝備名稱原本已有中文。開法術視窗時，視窗覆蓋原版英文文字框的右端，
完整矩形比對不再相同，既有事件被整則撤除，左側未遮住的名稱因此回到英文。
使用者要求完整中文覆蓋。修補維持原版視窗位置與遮擋，只保留仍可見的既定譯文。
不改文字、字型、遊戲規則、存檔或原版記憶體。

## 已量證據

R984正式前端、倚天3倍正常冷LOAD後，兩次法術開窗都可重現。
3257事件、1614發布，正常GUI／同binary正式重播／私人API重播／無覆繪控制均完成。
原版1MiB RAM、Regs、Step／Ticks、indexed與palette逐發布相同。
額外唯讀事件診斷亦全1614發布相同，158筆事件觀察只讀既有覆繪與indexed。

confirmed於此收據：發布1494的Step339400000及1586的375200000，
LONGSWORD、LEATHER/CUIRASS、FUR/LEGGING、SANDALS、BUCKLER/SHIELD的既有Shown為true，
原版矩形比對變false；不符點全部在x≥49，下一發布不再保留五個名稱事件。
CAST及CANCEL於本次矩形比對仍成立。這些是compose前旗標及一般rectEq，
以相鄰發布與正常GUI共同核撤除，不當特殊profile／roster／page守門的替代。

## 擬定契約與READY前缺口

- P1：辨識已證人物法術視窗，必須結合原文、呼叫位置、座標、字型／前景色與背景守門。
  本輪尚未量caller、font及fg色號，不能只按CAST／CANCEL或x≥49進production。
- P2：只有已證視窗遮擋區內的原版重寫可從原名稱比對中排除。
  可見區有任何未批准改寫仍撤除；整則過期、人物切換、取消返回與其他視窗照既有生命週期處理。
  不把矩形不符一律視作遮擋，不無限保留舊事件。
- P3：還原英文筆畫與繪製中文都排除新視窗遮擋區，不能覆蓋視窗、按鈕、咒語、游標或數值。
  保留原生15／16字模，遮擋由視窗自然裁切；不縮字、不截短正式譯文、不重排原版視窗。
- P4：一般裝備名稱與012複合名稱都要核。2倍的024整頁重排是另外一條路，
  未量實際背景／事件與遮擋前不得逕套一般文字矩形守門。
- P5：雙字型與2／3倍先做可丟棄原型，獨立核原字模、未遮區域及遮擋區像素。
  已批准視窗外差異需只落在名稱覆繪；原版六類狀態保持，正常開／取消／再開要驗。
  未支援或未通過背景守門時保留既有安全行為，不能把prototype接正式路徑。
