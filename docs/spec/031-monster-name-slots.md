# 031：怪物名字固定欄位與譯名衝突守門

狀態DRAFT；2026-10-08；[#24](https://github.com/wicanr2/wizardry7-cht/issues/24)。
入口[R983](../goal/R983-collision-context-probe.md)，原始出處與勘誤沿[013](../re/013-print-pipeline.md)。

## 為什麼要做

既有抽取器從NUL後跳過零，再讀下一串，會把同欄殘留字元當成下一個名字。
PS、ON、LANCER、GUARDIAN四個跨家族歧異因此是假來源，不需要新增runtime情境判斷。
固定欄位修補又暴露23個英文鍵的既有譯名衝突，不能用最後覆寫選名。

## 已核證據與界線

固定本機SCENARIO.DBS的檔案SHA-256為
`b2cb0722122724d35d379bb10250d0eec51238d9b147c36be12177ef3d2462f6`。
位址基準是檔案偏移：記錄起點225272、stride232、共250筆；四格在記錄+72／88／104／120，
各16 bytes，只讀第一個格內NUL前的名字。其後殘字不是下一欄。
獨立只讀250×64 bytes：1000格非空、可列印ASCII、有格內NUL；231格在NUL後含殘留。
原型與獨立重算全同，93筆名字陣列變動，唯一鍵461→398、新增12／移除75。
此為confirmed固定輸入的欄位形狀，不提升真名／別名／單複數／鑑定選擇的runtime語意。

## 擬定契約

- M1：只修build-only抽取器；原版檔、遊戲記憶體、runtime、查表正規化與schema保持。
  固定250筆，各四格；保留idx、rec與欄位順序，不遇壞格就break產生部分catalog。
- M2：格內缺NUL、空名字、非可列印ASCII或短讀都中止。NUL後殘留合法且忽略，
  不要求補零、不掃到相鄰格或名字區外。不得藉增加讀取長度補猜名字。
- M3：建立譯文候選時保留每個英文鍵的idx／slot／ZH來源。
  相同英文鍵的不同譯文必須明確列出並拒絕發布；同值重複可合併，不能採後列覆寫。
  缺索引譯名與Big5失敗同樣中止。
- M4：完整驗證原文與譯文後才寫正式兩份JSON；驗證拒絕時兩份既有檔保持。
  暫存輸出與置換須有界、同檔案系統，例外清理，不留成功形狀的部分catalog。
- M5：23個異譯鍵的名稱決定另列可核對表與理由。未完成前不重生正式譯文、
  不把原型的12個last-write值變動當成正式名稱校正，不宣稱四碰撞已從正式catalog解除。
- M6：測試至少覆蓋格內殘字、截短、缺NUL、空名、非ASCII、跨格不讀、
  同鍵同譯／異譯及拒絕時舊輸出保持。真實250筆須與獨立16-byte切片逐欄一致。
  上屏與同狀態驗收只涵蓋正常實際觸發的鍵，未量其他怪物維持READY。
