# 006 — 流動文字（引擎折行成頁的段落）翻譯

狀態：READY（2026-10-01，#40 故事修訂審查兩輪與F26補審：首輪兩項阻擋；第二輪與F26補審均無阻擋，文字澄清已處理；未量防禦分支維持READY）。旁白原審查與驗收紀錄仍保留。

證據：`docs/re/017`（F1–F26）；覆繪與還原機制沿用 spec 001

## 為什麼要做

迷宮開場旁白與迷宮之前的開場故事，都由引擎把連續訊息行重新折行，再依列數分頁印出（F1–F6、F12）。印字入口看到的是折行後的片段，
與訊息邊界對不上，整句原文查表不會命中。旁白原本只有第 1 頁有中文，來自不在版控的 `story.txt` 逐列硬對應（F7），
第 2 頁起全是英文；故事同樣靠 `story.txt` 逐列對應。訊息庫中屬於旁白這種結構的段落有 2,906 個（F9），不能一頁一頁手工對應；
故事 31 頁的譯文則與訊息庫另一組重複的英文（F21）並存，需要以引擎實際取用的訊息 id 決定用哪一組。

使用者定案（2026-10-01）：採用現有訊息譯文表，排除保留 `story.txt` 逐列文案的方案；依原版訊息邊界分頁，`story.txt` 退場。
兩份來源有 28／31 頁不同，逐列來源可能帶入下一頁的半句；對照見研究 017 的 R670 追記。此決定不更動原版英文、分頁或輸入。

## 規格

### R1 資料：`workplace/bake/flow.json`

由 `tools/re/bake_flow.py` 從 `text/messages.json` 與 `text/story-trans.json` 產生（與 `xlate.json` 同樣是重建產物，不進版控）。

- **剝控制碼**：直接刪除 `<0x20` 的字元，不補空白。R2 的片段字串用同一個函式。
- **行**：剝控制碼後，去掉行首一個 `@`。下列行「被排除」，且截斷所在的段落：含 `& % ] ^ $ # ! "` 任一字元、
  含數字、含（行首之外的）`@`。訊息 id 2500–2574 一律被排除。
- **段落**：連續訊息 id 的未被排除的行組成一個段落；相鄰以原始 id 計（`id＝前一行的 id＋1`，前一行被排除就截斷）；
  原文（剝控制碼後）行首是 `@` 的行開新段落。剝完後沒有字詞的行（零字詞）不被排除、維持 id 相鄰，
  但不加字詞、不記 `end`；沒有任何字詞的段落丟棄。
- 每個段落記字詞序列（各行以單一空白相連後依空白切開）與每個有字詞的行的 `end`（該行最後一個字詞的位置＋1）。
- **每行譯文 `zh`**：取 `story-trans.json` 同 id 的譯文，顯示副本先剝 `<0x20`、不補空白；非空、且每個字都能編成 Big5 雙位元組字、且能取得字形，才可用；
  否則 `zh` 為空（該行不可翻譯）。
  正式來源仍保留控制碼；修正範圍與靜態驗收依[016](016-catalog-control-preservation.md)。本輪已驗基線投影的預期段落／行／可用行／全譯段落為`2906／6307／4921／2166`，沒有重跑原始全量flow；六筆新增可用值尚未量正常上屏，歷史收據數字保持。
- **字形表**：每個用到的字一份 15 列位圖，取自 `bake_font.glyph_scaled`（15 位元、靠右；與 `xlate.json` 同一函式），
  取字形失敗（`glyph_of` 拋 `ValueError`）視為 `zh` 空。不依賴 `xlate.json`，避免同鍵不同譯文互蓋（#24 盤點）。
- **訊息表 `msgs`**（R3b 用）：`messages.json` 每一則（id 2500–2574 一律不收），en 剝控制碼、去掉行首一個 `@` 或 `#`、
  再去掉行尾終止符（正規式 `\s*(?:&[%#|\[]*)+\]$`，有則記 `t＝1`）。剝完後只含 0x20–0x7E、不含 `@ ^ $ % & ] #`、至少一個字詞的才收
  （數字、`"`、`!` 可以）。`msgs` 是 JSON 物件，欄名為十進位 id 字串；每筆記 `w`（字串：字詞以單一空白相連）、`t`（整數 0／1）、可用譯文 `z`（字串）：story-trans 同 id 的 zh，
  同樣剝控制碼、行首 `@`／`#`、行尾終止符，再依上面「每行譯文」的可用條件（非空、Big5 雙位元組、取得到字形）；不合格則 `z` 為空。
  `msgs` 與 `paras` 各自獨立建置，互不影響（旁白 R3a 的段落數字不因 `msgs` 改變）。
- 缺檔：流動文字關閉，log 一行說明；片段仍照 R6 記錄，畫面保持英文。
- 建置輸出：段落數、可索引行數、譯文可用的行數、整段都可翻譯的段落數、`msgs` 筆數與其中 `z` 可用的筆數；
  另可加旗標 `--drop <id>`，移除含該 id 的整個段落，並移除 `msgs` 中該 id，產生測試檔。
- `tools/re/bake_font.py` 不再讀 `workplace/bake/story.txt`（該檔不在版控，兩個流動文字站都不依賴它）；
  `xlate.json` 的其他來源不變。

### R2 印字入口與頁的辨識

- 入口 hook 進入時**先**讀返回位址（`CS:[SP]`）：屬於流動文字呼叫點（範圍表）就走流動路徑，不查表；其他照舊。
- 流動路徑對每次印字取字串（剝控制碼），並做內容防呆：64 bytes 內須有 NUL、只含 0x20–0x7E、至少一個字詞；
  不合格視為本頁無效。字型 ID（`[SP+4]`）與進入時的 y0（`740C:0297`）一併記錄。
- **頁**：第一個片段須 `y0＝146`；之後每個片段須與頁同站、`y0＝上一片段 y0＋12`，一頁至多 4 個片段。
  不符（站不同、y0 不是 146 起頭、y0 不連續、第 5 個片段）就結束目前頁並開新頁；新頁首片段 `y0≠146` 時新頁無效。
  無效的頁保持英文，log 一行。頁記所屬站。
- **片段閘門**（於返回後檢查，全部成立才算有效片段；F13）：字型 2、筆畫色 0x55（差異像素眾數）、離屏差異框 `2×x0＋w−1` 在該站的中心閘門範圍內（範圍表）。
  任一片段不符，整頁無效。筆畫色在第 2–6 頁只有間接證據，驗收 4 以 6 頁的 `Fg` 驗證；若有頁不符，先量原因再調閘門，不放寬到任意色。
- 頁字詞序列＝該頁所有片段依序以空白切開再串接。
- 返回位址的認定沿用 spec 001 R2.2（SP＝進入 SP＋2）。片段沒有建立事件（無差異、無離屏、巢狀）時，通知該頁失效
  （`finish` 的各個提早返回與巢狀捨棄都要呼叫頁的失效函式）。
- **取訊息紀錄**（R3b 的來源，F17）：另掛 `0110:0582` 的進入 hook。`[SP]`（近呼叫的返回偏移）等於某個流動文字站的「讀取端返回偏移」
  （故事 `0xBFEB`）時，記 (步數, id＝`[SP+2]`)，保留最近 32 筆，並 log 一行 `流文 取 <步數> id=<n>`；其他返回偏移不記。
  hook 只讀，不改原版狀態；沒有任何流動文字頁時也照記（`-flow ""` 亦同）。紀錄保留步數，不只保留 id。
  另保存最近一個故事片段的實際返回步數 `storyLastReturn`（初值 0）；每個故事片段返回後更新，包含失效片段。
  新故事頁的入口先將更新前的 `storyLastReturn` 存為該頁下界 `readAfter`；若沒有此前的故事片段，下界為 0。
  這不是目前頁首片段的入口步數：第一則訊息在首片段進入之前已取得（F17）。
  所有步數與邊界使用 `uint64`。返回追蹤獨立於覆繪事件：每個故事入口先登記返回位置與 SP、註冊返回 hook，再做內容防呆及事件建立。
  hook 在位置與 `SP＝入口 SP＋2` 相符時先更新 `storyLastReturn`，才呼叫 `finish`；即使沒有事件，也必須更新。
  內容防呆、無離屏、無差異、閘門失敗都不可漏掉這項更新。若新故事入口到來時前個返回標記尚未配對（巢狀／遺失返回），
  標記邊界未知，本次執行後續故事頁拒譯並 log；不能把捨棄步數當作返回。此為失敗即關閉（fail-closed）的防禦分支，正常路線未量到。

### R3a 頁的比對與譯文：字詞比對（`bcfc`）

每個有效片段印完後重算一次：

1. 候選：所有 `(段落, a)`，使 `段落.字詞[a : a+n]` 等於頁字詞序列（n＝頁字詞數）。
2. 完成的行：段落中 `a ≤ end−1 < a+n` 的行（一行在它最後一個字詞印出的那一頁顯示）。頁從一行中間開始時，
   那一行的最後一個字詞若落在本頁，也算本頁完成（F5：第 3 頁只顯示 15004 的尾巴，15004 的譯文在第 3 頁）。
3. 每個候選各得一個譯文（完成的行的 `zh` 依序相接）。沒有候選、沒有完成的行、或任一完成的行 `zh` 為空：本頁無譯文。
4. 多個候選：只有全部候選的譯文完全相同才採用；否則本頁無譯文，log 歧義（候選數、頁字詞）。

### R3b 頁的比對與譯文：取到的 id 串（`be0c`）

故事引擎逐則以 id 取訊息，一頁的字詞序列等於該頁取到的 id 串的字詞序列（F18），頁的最後一則有終止符（F19）。
每個有效片段印完後重算一次：

1. 取「取訊息紀錄」（R2）的最後 32 筆，先限定 `readAfter < 取訊息步數 ≤ 本次片段返回步數`，再依取得順序取 id。
   `readAfter` 是本頁入口保存的前一個故事片段返回步數（R2）；整頁保持同一下界，不隨本頁片段更新。
   本頁沒有任何紀錄時無譯文，不能以此前頁的相同英文或其他訊息組補洞。
2. 對每個起點 s（0 起）：從 `ids[s]` 起依序累加各 id 的 `msgs.w` 字詞；遇到 `t＝1` 的訊息（含）就停，
   遇到不在 `msgs` 的 id（不含）也停。得字詞序列 `C_s`。頁字詞序列 W（n 個）是 `C_s` 的前綴（n ≤ |`C_s`|）就是一個候選鏈；
   id 串相同的候選只算一個。
3. 完成的訊息：鏈中「累計字詞數 ≤ n」的訊息（一則在它最後一個字詞印出的那一頁顯示）。
4. 每個候選鏈各得一個譯文（完成的訊息的 `z` 依序相接）。沒有候選、沒有完成的訊息、或任一完成的訊息 `z` 為空：本頁無譯文。
   多個候選：全部候選的譯文完全相同才採用，否則本頁無譯文並 log 歧義。缺字形同 R3a。
5. 結果：`Para`＝鏈的第一個 id，`A`＝0，`Lines`＝完成的訊息 id，狀態字串 `取:<第一個 id>`。
   英文片段字詞仍是必要比對鍵，取訊息 id 只限制本頁來源情境並保留出處；不得單靠 id 略過英文比對。
   英文與他組 id 重複（F21）時只使用本頁實際取到且英文相符的來源。

### R4 排版（每個繪製端各自計算）

`Draw` 與 `hdFrame` 的倍率可以不同（`-scale`、`-hd-scale`），且字形縮放不同：`Draw` 把字條放大 `hd＝max(1, scale÷2)` 倍，
`hdFrame` 逐像素 1:1。因此排版由各繪製端用自己的倍率 `k` 與字形放大 `hdf`（`Draw` 為 `hd`，`hdFrame` 為 1）計算，
不在快照節點算一次共用。

- **字形放大 `gs`**（#41，2026-09-30 使用者同意）：旁白中文 15 px 字形在倍率 3 只有 5 遊戲像素，比英文旁白小很多。
  `hdf≥2`（`Draw` 倍率 4 以上）時 `gs＝hdf`；否則倍率 `k≥3` 時 `gs＝2`，`k＝2` 時 `gs＝1`
  （倍率 2 的列距只有 24 px，放不下 30 px 的字）。放大是整數倍的像素複製，不重採樣。
  這條只用於流動文字；其他文字的字形大小不變。
- 字距 `pitch＝17×gs` 螢幕像素（15 px 字形＋2 px 字距，各乘 `gs`），列寬上限依站（範圍表）：旁白 184 遊戲像素（F5、F13 的英文最寬列 183）、故事 296（F12 最寬 294）。
- 每列最多 `N＝floor(列寬×k ÷ pitch)` 字（至少 1）：旁白倍率 3 為 16 字（一頁 4 列共 64 字）、倍率 2 為 21 字；故事倍率 3 為 26 字（一頁 104 字）、倍率 2 為 34 字。
- **分詞**：`……`、`——` 各視為不可拆的一個單位（佔兩字），其餘每字一個單位。
- **換行（串流）**：從第 i 個單位起貪婪填滿到 `N` 字，得列尾 j（不含）；再做避頭尾，重複至多 3 次且列內至少留一個單位：
  下一個單位（第 j 個）屬於 `，。、！？；：）」』》…—`，或本列最後一個單位（第 j−1 個）屬於 `（「『《` 時，`j←j−1`。
  取定的列為 `[i, j)`，下一列從 `j` 起重新貪婪填滿（因此每列字數必 ≤ N）。
- 最多 4 列；超過則本頁無譯文並 log。
- 每列水平置中於 x＝160：`X0＝160×k − n×pitch ÷ 2`（螢幕像素，整數除法）；`Y0＝(146＋12r)×k`（螢幕像素，r 從 0 起；不加 dy）。
  列距 12×k 螢幕像素，字形高 15×gs：倍率 3、`gs＝2` 時列距 36、字高 30。
- 依頁譯文、`k`、`gs` 快取排版結果，頁譯文改變時才重算。

### R5 疊圖：兩趟判定

**事件**：每個有效片段建一個「還原事件」：框、前後像素、筆畫色與 spec 001 R2 相同，不帶字形，並記所屬頁。

**頁事件的比對**（F15）：旁白筆畫在 A000 上會閃爍、也會淡入，色號不固定，逐像素相等會失敗。頁事件改用下列判準
（一般事件維持 spec 001 R3 的完全相等）：
- 「筆畫像素」＝事件框內 `before≠after` 的像素；其餘為「底圖像素」。
- 事件相符＝游標框之外，(1) 所有底圖像素與 `after` 完全相等；且 (2) 至少一半的筆畫像素與 `before` 不同
  （英文還在，色號不論）。
- 還原：相符的頁事件把所有筆畫像素（游標框之外）換成 `before`。
- 英文被擦掉（筆畫像素都回到 `before`）時 (2) 不成立，事件不再相符，這是偵測「頁已消失」的訊號；
  英文尚未 blit（筆畫位置還是 `before`）時同理不相符。
頁記：所屬站、片段數（已進入的有效片段）、事件清單、最後一個片段返回時的步數 `lastStep`、譯文、最後片段返回時的文字帶快照
（該站的帶 x、y 146–194 的離屏色號：旁白 184×49＝9,016 個，取 F2、F3 量到的英文範圍；故事 296×49＝14,504 個）、以及旗標（已計入 `shown`、已 log 帶不符、失效）。
`compose` 在判定趟結束後丟棄事件已全數被刪的頁，並回傳有效頁；`shared` 新增有效頁欄位供 `Draw` 使用。
`compose` 會被 `hdFrame`、autoplay 截圖在快照節點之外再呼叫，所以「計入 `shown`」與「log 一次」用頁旗標，不靠呼叫次數。

`compose` 分兩趟：

1. **判定**：對所有事件依 spec 001 R3 表判定 `match`、`pending`、`dropped`，就地壓縮存活事件；不還原、不畫。
   非頁事件在此趟照舊處理（維持 spec 001 的行為）。
2. **裁決**：對每一頁，同時成立才「有效」：
   - 頁有譯文；
   - 事件數＝已進入的有效片段數；
   - 每個事件本趟都是 `match`；
   - 距 `lastStep` 至少 200,000 步（中間態不畫：一頁的各列間隔約 44,000 步，可能跨快照）；
   - **文字帶靜態檢查**：A000 在該站的文字帶內、游標框之外，與 `lastStep` 時的離屏帶快照，在頁所有事件的筆畫像素之外逐像素相等。
