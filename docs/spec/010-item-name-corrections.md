# 010：物品名稱錯配校正

狀態：READY；2026-10-01；[#22](https://github.com/wicanr2/wizardry7-cht/issues/22)、
[#24](https://github.com/wicanr2/wizardry7-cht/issues/24)。
入口[R672](../goal/R672-delivery-prerequisites.md)，證據[019](../re/019-catalog-migration.md)。

## 為什麼要做

使用者要求完成中文化，並選擇先逐組統一譯文再遷移。
417筆原文與原版名稱欄逐筆一致，但手填中文索引已有連枷、長杖、弓箭等錯配。
本規格只校正已審閱的28個名稱，不改原版物品編號、效果、裝備規則或資料格式。

## 證據與文案

原名來自`SCENARIO.DBS`檔案偏移`896 + 72 × idx`的32-byte名稱欄，
不是IDA位址或runtime情境值；來源雜湊與417筆核對見019。
獨立名稱審閱見`workplace/r698/items-review.json`及`items-followup.json`。
普通武器詞義與既有術語支持校正；名稱不能當作實際戰鬥效果證據。

## 契約

- I1：只改上表28個完整英文鍵的顯示譯名。idx只作來源核對，不能進入執行期匹配。
  原版檔、英文抽取表、覆繪位址、輸入、存檔與規則保持原值。
- I2：目前正式來源尚在JSON遷移階段，同步修正`text/items-trans.json`與
  `tools/gen_items.py`既有28筆`ZH`，避免重生時還原錯配；不新增第二份執行期譯表。
  下列共用名稱另同步`text/story-trans.json`及`tools/gen_trans.py:Z`的兩筆；
  `batches-merged.json`沒有這兩個來源，不新增或修改它們的批次文案。
  #24正式遷移時上述JSON與產生器的內嵌譯文退場，唯一來源改為規格008的TSV。
- I3：先稽核訊息、怪物、F1及烘製正規化鍵交集。相同英文且相同名稱語意須一起統一，
  但未證實同義或正規化碰撞不能默認由物品覆蓋。需要不同情境時仍由008阻擋，
  不新增虛構caller／ID情境或私改正規化來讓它通過。
  安全訊息3805的`WALRIBLADE`在怪物武器名稱族，與物品38的同一英文武器名稱
  共用譯名「瓦爾里刃」；實物紀錄及效果對應仍未知。
  5506的`SLING`在武器技能名稱族，與物品29共用武器名「投索」。這是同名稱術語統一，
  不將訊息來源ID註冊為執行期情境，也不宣稱兩者物品效果相同。
  原名定位已證實，名稱族的同義連結按原文／既有分類為強推論，正式採用前須獨立核對。
- I4：每筆完整英文、來源索引、控制碼數量保持；中文須可Big5編碼、全形字數不超過
  原文字元數的一半、兩字型缺字0。未經證實的更大畫格不能用來豁免欄寬。
- I5：譯名表記錄新文案與證據限制；F1名稱表按現有工具重生，按上表完整英文鍵及
  兩個訊息出處檢查舊錯配已移除；不全域禁止仍屬其他物品合法名稱的舊中文字串。
  所有顯示影響先保存來源交集與原始基準，避免文案變更被寫成格式回歸。
- I6：烘製兩字型並核對28筆及兩個共用訊息的字形與英文鍵。正常角色／物品頁做
  倚天／Unifont與2×／3×共四組正式覆繪，對照同輸入關閉覆繪的基準，
  Mem／A000／Pal／Step應相同，畫面差異限於批准的覆繪區域。
  正常路線未觸發的物品只稱「名稱校正及靜態驗證完成」，不稱28個上屏路徑全CONFORMED。

## 審查與驗收界線

`r705/items-impact.json`核對28筆完整英文／索引、怪物／訊息／F1及兩種既有正規化算法：
物品候選內碰撞0、額外正規化交集0，只有I3列明的兩個安全訊息共用名稱。
`r705/runs.json`及360M角色概覽／400M道具操作頁的關閉、倚天、Unifont三組3×基準，
Step／Mem／A000／Pal與原始A000、色盤位元組全同；本輪28個校正名稱觸發數為0。
修正後`r715/report.json`完成兩字型×兩倍率與關閉覆繪的六組／十二張快照，
獨立核對1,366項、失敗0；原版狀態雜湊及A000／色盤位元組全同，批准區外像素差0。
四張3×中文快照與r705的Shown／合成／PNG逐位元相同。
本輪28個校正完整鍵仍未觸發，名稱上屏範圍維持READY。

`r714/item-changes.json`保存28個物品與兩個共用訊息的精確來源差異；
兩個產生器重建譯表逐位元相同，原始物品表與F1名稱表不變。
`r714/independent-item-fonts.json`直接解析兩份原始字型，64項核對、失敗0；
全量烘製字形及流文只有批准的28筆／兩訊息差異，其他內容與舊基準相同。
新正式字元清單2,925項，需用非ASCII 2,878字、兩字型缺字0。
舊無差異回歸器的兩項文案差異另保留，不作本規格失敗或放寬全量比較。

首輪審查與窄複審見`r706/item-spec-review.json`、`item-spec-r2.json`；
複審無實質阻擋，僅要求補入上述已量範圍與0/28界線，現已補正而轉READY。
驗收需保存修正前後雜湊與精確差異集合，
產生器重生資料與正式表一致，字型重建／F1名稱／原版狀態隔離通過。
未在正常玩家路線觸發的名稱及未知發音留在READY範圍，不能以單元測試抬升完成聲明。
