# R983 剩餘碰撞的正常情境與譯名取捨

2026-10-08，沿[#24](https://github.com/wicanr2/wizardry7-cht/issues/24)、008 DRAFT及R969既有裁決。
目前正式32組為11訊息與21跨家族。R981、R982已完成項不重開。

1. 從三正式catalog核32組，保留原樣英文鍵與所有語意差異。
2. 使用者2026-10-08選定BASELARD＝巴塞拉短劍。只同步3816與有效Z來源、譯名表；
   英文鍵、物品資料與規則保持。五字另核雙字型及實際字條寬度，未量上屏不稱已驗。
3. 另從合法新保存正常LOAD，查看人物頁／選單等可到達畫面，核既有29出處是否觸發。
4. 窄觀察只限已授權出處與最多64 bytes目的緩衝；不讀鄰文或整個答案表，不注入角色／位置／state。
5. 正常觸發後才整理分流訊號與DRAFT增補；未READY不進正式runtime，未量到不稱分流已解。

共同決策沿grilling，顯示與語意隔離入口已載入。研究收據留workplace/r983，現況CONTEXT、歷程WORKLOG。
Docker沿固定映像、network none、1000:1000、限額、逾時及有界Xvfb；原版／字型／SDK唯讀，R433保持未追蹤。

另發現四個怪物鍵疑似抽取錯欄：既有names_at跳過NUL後殘字，250筆原始名字區為16-byte固定格，
起點72／88／104／120；最初15-byte假說已由精確起點否定。
優先窄核既有怪物資料與固定欄位，不延伸MSG旁文；先原型及證據審查，不逕改正式表或把假說作新規則。

獨立重算250筆／1000格與原型全同，四殘片鍵無須新增情境分流。
固定欄位修補及23個既有譯名衝突分開，契約入口[031](../spec/031-monster-name-slots.md)。
BASELARD範圍由[011增補](../spec/011-message-wording-unification.md#r983-baselard-unification)承接。

BASELARD增補獨立審查0／0／0已採認READY後同步正式來源，雙字型完整重生及候選逐bytes核對通過。
原樣英文鍵異譯32→31，只解除該名字；正常3816上屏及第三項profile／29來源探測本輪未量。
