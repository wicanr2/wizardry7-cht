# R928 角色列表的性別與職業文字

2026-10-04；[#22](https://github.com/wicanr2/wizardry7-cht/issues/22)、[#28](https://github.com/wicanr2/wizardry7-cht/issues/28)。R930契約及R931實作、結果複審均0／0／0，022採認為READY。六列3倍雙字型、正常GUI選取／取消及20對原版摘要驗收通過；2倍保持原版英文，仍未達完整中文，沒有批准降低交付門檻。結果見[025](../re/025-ui-localization-coverage.md#r928-正式六列覆繪)。

使用者要求所有按鈕與訊息完整中文化，包含圖片按鈕。[025的R921](../re/025-ui-localization-coverage.md#r921-新增角色對話框)已證實新增角色清單有六列「姓名＋性別職業碼」動態文字未譯，來源為resident返回位置0110:0fcc，x150、y150／156／162／168／174／180。姓名依[names](../names.md)保留英文；性別與職業需要中文。

本輪先回答一個問題：原版印字及合成資料是否足以可靠識別性別職業碼的目的矩形，並在覆繪時完整保留姓名？先查已封存的正常GUI證據、原版indexed畫格及既有resident印字管線。不從可見字串猜角色record偏移，不把六個預設名字推廣成任意角色格式。

必須量到英文姓名與碼各自的實際筆畫範圍、原版字距、列表可用範圍、兩倍率原生中文字形的容納條件，以及列選取／取消後的生命週期。證據不足就明列下一個窄範圍探針，不以既有畫面正常推論新分支完成。會改變正式玩家排版時，先提出可檢視原型及所需取捨。

沿用R921／R925原版、SDK、字型與收據，保持唯讀。本輪不讀MSG.DBS、messages.json、手冊答案或對話詞庫，不啟用autoplay、防拷作答、作弊或注入狀態。所有分析與執行只在離線非root、受資源及外層逾時限制的Docker；新證據只寫workplace/r928，不覆寫先前封存。先完成證據與DRAFT規格，再按獨立審查、READY、實作及正常GUI／同狀態驗收推進。證據入口回填025，歷程寫WORKLOG，最新狀態寫CONTEXT，議題保持開啟直到完整驗收。
