## 擷取契約

1. 使用R915正式binary及雙字型資源，先核既有SHA，原版、SDK、字型及已封存R915全部唯讀。輸出只在workplace/r921，既有目的地即拒絕。沒有新正式Go、譯文或生成器變更。只在Docker執行，非root、network none、相稱資源與外層逾時；Xvfb及遊戲有finally清理，不留下程序。
2. 第一段只跑Unifont3×的實際GUI，靜音並明示手動-ips 24000000，原版CPU／PIT不改。固定取得272M、400M、528M的完整HD、JSON及實際Draw。這些步數是取樣點，沒有狀態注入。無autoplay、作弊、seed重擲、名字或任何其他文字輸入；不進設定、匯入、防拷或開始遊戲。
3. 272M的完整HD及Draw、JSON步數、六個主選單訊號核對後，控制器只可透過實際視窗F1暫停，核「說明 true」日誌。主代理先看本次主選單畫格，再由GUI F1恢復、確認「說明 false」後，只單擊320×200遊戲座標160,62，對應3×實際視窗座標480,186。核正式「左鍵」成功日誌；不得用o.Click、clicks-at或寫記憶體代替本段GUI輸入。
4. 400M完整擷取後，同樣F1暫停，主代理檢視對話框及原版色號／色盤。下一次只可單擊本次已見且可定位的取消按鈕，位置須由可見控制及原版邊界支持，記錄選點及依據。看不到取消、來源不清、出現其他頁或需要文字輸入時停止，不猜點、不反覆點擊。F1恢復並核日誌後才送一次取消。528M核是否返回原主選單，沒有新增角色或原版存檔寫入。
5. 取得每份PNG須完整解析及尺寸正確，JSON的Step須精確，Draw完成日誌須存在。正常WM_DELETE_WINDOW退出碼0及10秒內退出才計通過。每段擷取等待180秒、主代理看圖／選點等待120秒，整趟容器外層上限600秒，等待工具每次不超過60秒。逾時與強制停止列失敗，finally只清自有程序。正常退出後檢查UID/GID、原版248檔及自有容器。

## 同狀態及中文核對

- 真實GUI點擊時點不決定性，第一段只驗對話框出現、中文及取消返回，不拿兩次GUI的不同輸入時點作原版雜湊對拍。
- 第一段須先核新增與取消位置、取消成功、528M返回原主選單及沒有原版存檔寫入，才可另以既有clicks-at測試入口作固定步數輔助：280M單擊新增，440M單擊已量取消；於272M、400M、528M取HD及實際Draw。倚天／Unifont各2×、3×及英文2×、3×，共六次，不啟用F1、autoplay或其他輸入。任何取消或返回證據不足即停止，不執行輔助段；固定路線不能重現本次已見畫面亦停，不調種子或猜補輸入。

## 存檔驗收修訂（READY）

第一次控制器誤用舊版左鍵日誌格式，第二次成功取消返回，但「存檔目錄必須空白」斷言失敗。唯讀雜湊核對顯示唯一PCFILE.DBS為9368 bytes，與原版輸入完全相同，SHA-256均為24d94441e5b32e7abbcbffa9dad972b41544da6a7bb06096b967281f639d9c1b。[014](../spec/014-original-save-storage.md)已規定原版寫開既有檔案時複製到獨立可寫層；不能把這個未改內容的複製視為新增角色。

修訂只調整本輪驗收判準，不改正式程式或原版行為：

- 在272M及528M保存存檔層檔名、類型、大小、SHA及UID/GID；目錄拒絕symlink、非一般檔案及額外檔案。272M須空白；528M只允許空白或單一PCFILE.DBS，若有則須與唯讀原版逐位元組相同。原版248檔仍逐檔不變。
- 對外結果寫「沒有新增角色或變更存檔內容；獨立層可能有未改內容的PCFILE複本」，不寫零檔案或零DOS寫入。僅憑內容相同不宣稱沒有DOS寫入。
- 先以同一實際GUI路線乾淨重跑，成功取消、528M返回、上述內容判準與正常WM_DELETE退出全部通過後才跑六次輔助。輔助同樣核存檔內容與中英文等同。
- 左鍵確認改依現行main.go的「左鍵 (x,y) steps=N err=」格式；只接受新操作後的非負步數及空錯誤碼。其餘輸入、逾時、唯讀、停止及失敗片段保留規則不變。第二次片段不得改成成功。

### 輔助檔案取樣時點修訂（READY）

固定272M的HD／JSON先生成，控制器等待GUI Draw並解析PNG時，原版可能已執行280M新增點擊。因此之後讀到的存檔層不是272M的固定步數快照。兩個2×輔助首跑因此在空目錄斷言停止，未到400M與正常退出，均保留失敗片段；不修改步數、輸入或節流來避開。

只修正輔助檔案取樣方法：每個全新case在啟動遊戲前建立空的獨立saves，核UID/GID、無symlink及空目錄，記為before_launch。每次完整畫格後及正常退出後另記檔案清單與時間，明示它是控制器實際讀取時的內容，不能標為該畫格Step的精確存檔快照。允許的內容仍只為空白或單一同原版PCFILE；其餘檔案、型態、連結、內容變更仍失敗。原版、SDK及來源仍保持，實際GUI先成功的前置不變。HD／JSON的Step及原版狀態對拍保持精確，不降低內容相等與正常退出判準。
